ひとめぐり　星空教本　後記

後記
換一種寫法

這本書從頭到尾用的是原生的 three.js：自己建場景、自己把東西加進去、自己跑迴圈。實際做網站時，很多人會在上面再套一層框架。這一篇把同一個成品用 TresJS（Vue 的 three.js 框架）重寫了一次，看它省了什麼、又拿走了什麼。

打開 TresJS 版 ↗

兩邊看起來應該一模一樣。差別全部在程式碼裡。

01　DECLARATIVE

同一顆星，兩種寫法

這是原生的寫法，也是第二章教你的那四行：

const shape   = new THREE.IcosahedronGeometry(1, 2);
const surface = new THREE.MeshStandardMaterial({
  color: 0xecdcae, roughness: 0.45, flatShading: true });
const star    = new THREE.Mesh(shape, surface);
scene.add(star);

這是 TresJS 的寫法：

<TresMesh>
  <TresIcosahedronGeometry :args="[1, 2]" />
  <TresMeshStandardMaterial color="#ecdcae"
    :roughness="0.45" flat-shading />
</TresMesh>

上面是命令式：一步一步告訴電腦「做這個、再做那個」。下面是宣告式：只描述「場景裡有什麼」，建立、加進場景、之後的更新和清除，都由框架去做。

注意那些名字：IcosahedronGeometry、MeshStandardMaterial、roughness、flatShading。一個字都沒變。框架換掉的是「怎麼組裝」，不是「組裝什麼」。

所以這本書的詞彙在框架裡完全通用。你描述畫面的方式不需要改。

02　WHAT YOU GET

框架替你做的事

重寫的過程中，這些事不用再自己處理：

開場的雜事
建立 renderer、接上 canvas、視窗縮放時更新相機和解析度。原生版要十幾行，這裡是一個 <TresCanvas>。
加進去，和拿出來
模板裡有的東西就在場景裡；條件不成立就自動移除，並釋放它佔的記憶體。原生版的「拆鷹架」每一樣都要自己記得。
旋鈕
屬性可以直接綁資料：資料一變，場景跟著變。這本書為了做到這件事，自己寫了一整套「場景參數」的機制。
指標事件
在物件上寫 @click、@pointerenter 就好。第十章的射線檢測，框架在背後替你做了。
和頁面其他部分說話
場景就是一個 Vue 元件。頁面的狀態（讀到哪裡、載入好了沒、現在是什麼語言）可以直接傳進去。

省下來的幾乎都是「接線」。這些事不難，但很瑣碎，而且容易漏。

03　WHAT YOU GIVE UP

框架沒有替你做的事

TresJS 版的場景檔是 186 行，其中宣告式的模板只有 44 行。剩下的四分之三，和原生的寫法幾乎一樣：

每一幀的動作
自轉、漂浮、彈簧、相機運鏡、四十顆小星的位置，還是要拿到物件、在每一幀親手改它。宣告式只描述「有什麼」，不描述「怎麼動」。
Shader
GLSL 原封不動。兩個版本用的是同一批檔案。
粒子的資料
兩千多顆星放在哪裡、多亮，還是那個迴圈。
後製
框架預設「畫完直接上螢幕」。要插進後製，得把它的渲染那一步換成自己的；或者再裝一個後製套件，多學一套寫法。
踩過的坑
第八章「後製下底色變灰」的問題，在這裡原樣再出現一次。框架不會替你擋掉 three.js 本身的行為。

另外多了一樣東西：出錯的時候，你要先分辨問題在 three.js 還是在框架那一層。如果不懂底下那一層，這一步會很難。

框架把簡單的事變得更簡單，困難的事維持一樣困難。這本書教的，剛好是困難的那一半。

04　CHOOSING

所以，正式的開場該用哪一種

原生 three.jsTresJS
建立與清理自己寫、自己記得框架處理
旋鈕與頁面狀態自己做一套機制直接綁資料
點擊與懸停自己射線檢測寫在物件上
每一幀的動畫一樣：拿到物件，每一幀改它
Shader、粒子一樣：同一批程式碼
後製直接接上要繞一步
渲染迴圈完全在你手上在框架手上，要用的時候借出來
除錯一層兩層

我的建議分兩種情況：

如果網站本身是用 Vue 寫的，開場用 TresJS。開場不是孤立的一頁，它要知道頁面載入好了沒、使用者捲到哪裡、什麼時候該讓位給內容。這些「和頁面說話」的事，正是框架省最多的地方。

如果開場是獨立的一頁，或網站不是 Vue，用原生就好，像這本書一樣。為了一個場景多背一層框架不划算。

不管哪一種，都把 shader、粒子的資料、動畫的算式寫成和框架無關的獨立檔案，就像這次兩個版本共用同一批 shader。框架只當外殼。這樣以後要換框架、或把框架拿掉，核心的東西一行都不用重寫。

這本書到這裡結束。你從一塊黑色開始，現在知道每一樣東西是怎麼來的、該怎麼說、以及哪些可以不要。
